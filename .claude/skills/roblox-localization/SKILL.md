# Roblox localization and internationalization

Use for translating UI, prompts, tutorial copy, or messages. Combine with `game-ui-ux` and `roblox-cross-platform-accessibility` for layout and input. Before live changes, inspect `get_studio_state`, `survey_place(includeSource=false)`, existing GUI, scripts, translation tables and the experience's established localization workflow. Do not assume all text comes from a single table or that automatic translation covers dynamic strings.

## Workflow
1. Agree on source language, target locales, scope, and a fallback for missing translations. Inventory visible text and dynamic messages, including empty/loading/error states; distinguish player-generated text from authored copy. Preserve meaning and context for reviewers. Don't send private user data to a translation service or copy it into logs.
2. Reuse the project's `LocalizationTable` and `AutoLocalize` conventions where applicable. For dynamic messages, use the project's localization/formatting approach rather than concatenating translated fragments; preserve named parameters and context. Confirm current Roblox API behavior and fallback for the actual experience before introducing an unfamiliar API. Do not overwrite existing translations or publish changes without authorization.
3. Prepare a small, caller-supplied set of entries: `{"key":"reward","source":"Earn {amount} coins","translations":{"fr":"Gagnez {amount} pièces"}}`. Call `audit_localization` with these entries and `locales:["fr"]` to check named or numeric parameter consistency, format differences, duplicate keys, and missing translations. Format differences are review flags, not necessarily errors: locale-specific formatting may be intentional. Unsupported or unmatched brace syntax is flagged for manual review; double braces, parameter types and repeated occurrences are not validated. Paginate issues with `nextCursor`. This checks only the provided text and locale keys; it does not read or modify translation tables. Adapt the input from a reviewed export rather than assuming this shape is Roblox's native export format.
4. For dynamic Roblox translations, consult the [Roblox parameter reference](https://github.com/Roblox/creator-docs/blob/main/content/en-us/production/localization/translate-dynamic-content.md) for named and positional parameters and specifiers (for example `{1:num}` or `{Place_Name:translate}`). Verify lookup and argument types in Studio; the offline audit cannot prove they work.
5. Design for longer or shorter text, different scripts, line wrapping, and varied number/date conventions. Avoid fixed English-sized buttons, text baked into images, and UI state encoded only by color. Check the project's font glyph coverage and whether right-to-left presentation is needed; do not claim automatic bidirectional support without testing it. Ask a qualified language reviewer to check context and translations.

## Verification
Run `luau_check` before script writes and persist approved edits in `dm="edit"`. Use `audit_ui_layout` as a layout heuristic and `capture_viewport` or `screenshot_gui` to inspect rendered results; neither proves translation quality or complete coverage. In a connected Studio playtest, verify actual translation lookup, fallback, dynamic parameters, loading/error states, glyphs, long text, scrolling and console output in each target locale. Test representative real devices and input modes where available, with human review for meaning. Report locales, devices and fallback paths not tested; an offline audit, mock or screenshot alone cannot establish localization correctness.
